- **Upgrading from v0.12.0** ([guide](upgrade.md#upgrading-from-v0120), #2118) — the steps from v0.12.0, v0.12.1, v0.12.2 or v0.12.3 to v0.13.0, with the changes to read first: `graph.readerNamespaces` is removed (check `helm get values`, and upgrade with a values file without it if you set it), a rollback changes only its target environment when its artifacts are pinned by digest and were verified upstream, gate changes reach the versions in flight, `provenance.ciRunURL` refuses credential parameters, only the controller changes the rollback markers of its own Bundles, kardinal neither adopts nor overwrites someone else's commit on its PR branch, and a namespace named in `spec.policyNamespaces` must agree to share its gates. It names the new CRDs, the receipts admission policy and the auditor roles, says that EKS health credentials stay off until roles are allowed, and that kro stays at the same version. The downgrade notes and the v0.8.1 guide's note on reader bindings now say which release each applies to. Two new live suites, `upgrade-v0120` and `upgrade-v0121`, run the steps as written on Kubernetes 1.35 and 1.37 while versions are in flight: versions keep their Graphs, steps and PRs and finish; gates that hold a version keep holding it, and an edited gate reaches it; approvals and Verdicts recorded before the upgrade count, and an AgentRun running at the upgrade finishes and counts; an automatic rollback v0.12.1 started is the same rollback after the upgrade; the PromotionReceipt and ChangeRequest kinds are installed and stay inert until you use them; the reader RoleBindings of v0.12 are removed.
