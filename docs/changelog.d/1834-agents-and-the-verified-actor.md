- **Agents and the verified actor** (#1834, [page](actors.md)) — every version, Approval and gate override records its *actor*: `kind` (`human`, `agent`, `bot` or `controller`), `principal`, and for an agent its `agent` and `sponsor`, in the record's `spec.actor`. A new cluster-scoped `AgentIdentity` registers an agent: its subjects (ServiceAccounts, users or groups), its sponsor (a person), its scope (namespaces, Pipelines, environments), its autonomy, and `suspended`. The controller validates each one (`status.ready`: a subject two AgentIdentities claim stays with the older; an agent cannot sponsor an agent) and builds the release's `AgentIndex` (the chart creates it, and only the controller may delete it or write its status), which the new `<release>-actor` and `<release>-actor-overrides` ValidatingAdmissionPolicies read: a stamp must say exactly what the requester is, an agent must stamp and stay in its scope, and a suspended agent is refused. An AgentIdentity is deleted only once suspended. A write that adds a gate override carries the label `kardinal.io/override-check: "true"` (`kardinal override` and the UI set it), so kro's re-applies of gate instances that were never overridden skip the index (an override written without the label is refused: see Upgrade); `helm uninstall` keeps the AgentIndex (`kubectl delete agentindex <release>` afterwards). The CLI (`create bundle`, `ship`, `promote`, `rollback`, `approve`, `override`), the UI and the Bundle API stamp for you; what a client asserts about itself (`KARDINAL_ACTOR_MODEL`, `KARDINAL_ACTOR_SESSION`, `KARDINAL_ACTOR_CLIENT`) is kept apart under `asserted` and never trusted. The actor shows in `kardinal history` (an `ACTOR` column), `kardinal why`, the stage drawer ("Shipped by"), and the PR's "Created by" line. The registry is readable by every authenticated user (`actors.directory.public`)
