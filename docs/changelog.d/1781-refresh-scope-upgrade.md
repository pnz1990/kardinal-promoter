- **Pipelines whose GitOps objects are not in or deploying to their namespace no longer refresh Argo CD or Flux** (#1781) — their steps now wait for the tool's poll, with `refresh skipped (...)` in `status.refreshMessage`. Three layouts are affected: Applications or Kustomizations that deploy to other namespaces (a Pipeline in `default` and Applications deploying to `my-app-prod`: add `default=my-app-*`); objects that name no destination namespace, which are judged by their own namespace, including Flux's default layout of Kustomizations in `flux-system` without `spec.targetNamespace` and Applications without `spec.destination.namespace` (add `default=flux-system` or `default=argocd`, which admits every such object there for Pipelines in `default`); and Applications that deploy to another cluster, or Kustomizations with `spec.kubeConfig`, which are judged by their own namespace too (add `default=argocd` or `default=flux-system`). A Kustomization's source GitRepository in another namespace must be admitted itself (`default=flux-system` for a shared one). Set these in `health.refresh.namespaces`; `["*=*"]` restores the behaviour before v0.12 ([Sync on promotion](health-adapters.md#sync-on-promotion))
