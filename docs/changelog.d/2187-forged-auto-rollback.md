section: Security

- **A forged automatic rollback is never adopted** (#2187). `onHealthFailure: rollback` and a RollbackPolicy took any Bundle of the pipeline as the automatic rollback when it had the `kardinal.io/rollback` label, `kardinal.io/rollback-from` naming the failing version and its environment as target, at any name. Anyone who may create Bundles can set those fields, so they could pre-empt the rollback: the step said it was rolling back while the environment stayed on the failing version, or rolled forward to a version of their choosing through the normal gates. kardinal now adopts only a Bundle the controller created, with its actor stamp (`kind: controller`, `via: auto-rollback`) and creator, which the chart's admission lets no one else write ([What Happens in Git](rollback.md#what-happens-in-git)). The same markers no longer steer the rollback planner either: a release labelled a rollback by its author is rolled back automatically (only the controller's own automatic rollback is exempt), and only a rollback the controller wrote (automatic, or from the UI or the Bundle API) marks a version as rolled back from. A rollback created with kubectl or `kardinal rollback` no longer does; name the version with `--to`.
