section: Fixed
---
- **`fail-on-alarm` fails a target deleted after the bake window started, and an abort is dated by its last update** (#2006) — a target that is not found under `bake.policy: fail-on-alarm` waited for the first healthy check also after a window had run and stopped, so a deleted Deployment, Rollout or Application failed only at `health.timeout`, with the message `waiting for the first healthy check`. Only a target never found healthy (`status.bakeFirstStartedAt` unset) now waits; after that, not found applies `onHealthFailure`, and a stopped window reports `waiting for a healthy check to restart the window`. An Argo Rollouts abort that an earlier release may have left is now dated by the `Progressing` condition's `lastUpdateTime` rather than its `lastTransitionTime`, which does not move when the condition was already `False`, so such a real abort is no longer taken for the earlier release's ([argoRollouts](health-adapters.md#adapter-argorollouts), [Rollback](rollback.md)).
