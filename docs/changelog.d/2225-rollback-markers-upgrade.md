---
section: Upgrade
---

- **Only the controller changes its own rollback markers, and labels no longer make a rollback** (#2225, #2187) — on a Bundle the controller created, the `<release>-bundle-creator` admission policy refuses anyone else's add, change or removal of the `kardinal.io/rollback-from` annotation and the `kardinal.io/rollback` and `kardinal.io/pipeline` labels, so a script or GitOps tool that relabels those Bundles gets an error. New rollbacks record the version they roll back from in `spec.provenance.rollbackFrom` (apply the CRDs first); rollbacks v0.12.0 created have none and are still found by their name. An automatic rollback adopts only a Bundle the controller created as that rollback. The controller's own automatic rollbacks are never rolled back again, as before; any other version labelled `kardinal.io/rollback` is exempt from an automatic rollback only when every artifact it deploys was Verified in that environment before; v0.12.2 already adopts and exempts so (#2187), and from v0.12.0 or v0.12.1 both are new. This applies to what is in flight when you upgrade: the admission rule covers the Bundles the controller created before the upgrade too, and a labelled version already promoting whose artifacts were never Verified there is rolled back automatically when its health check fails, where v0.12.0 and v0.12.1 stopped it for a person ([What Happens in Git](rollback.md#what-happens-in-git)).
