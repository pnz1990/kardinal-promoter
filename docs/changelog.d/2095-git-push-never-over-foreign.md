- **git-push never force-pushes over someone else's commit on kardinal's PR branch** (#2095). A step that pushed again, after a controller restart or a retry, overwrote any commit someone had pushed onto `kardinal/<hash>/<bundle>/<env>` in between, silently. git-push now reads the branch's head first and pushes, with a lease on that head, only when the branch is absent, its head is one of the commits the promotion pushed, or its head's commit has the same tree and parents as the one to push (a deleted PromotionStep's own push, found by the step created again, which keeps working as before). That head is compared by fetching its commit object alone, never its files, and is recorded apart from kardinal's own pushes. Otherwise it pushes nothing, and the step fails against its retry budget with a `PRBranchForeignCommit` Warning Event and `status.outputs.prForeignHead`, as open-pr does. The PR branch's rebuild on a moved base uses the same check ([PR evidence](pr-evidence.md)).
