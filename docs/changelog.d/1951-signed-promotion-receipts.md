- **Signed promotion receipts** (#1951) — with `receipts.enabled`, every promotion that reaches Verified gets a PromotionReceipt: an in-toto SLSA verification summary whose `kardinalPromotion` record names the version, the actor and sponsor, the gates as they were when the step started, the approvals, the checks and the PR. The controller signs it (keyless through Fulcio, or a key in a Secret; `receipts.signing.mode: kms` is refused at start, since the published image has no KMS provider yet, #1952), keeps it in the cluster, and with `receipts.sinks` pushes it as an OCI referrer of each image and logs it in Rekor; it comments on the PR once. `kardinal verify-receipt` checks a receipt from the cluster, an image or a file, and fails on any change made after signing. `kardinal history` and `kardinal why` show the receipt. A receipt never signs a credential it can recognise: before signing, every string of its record and every subject name loses a URL's user info, the value of a credential query or fragment parameter, and GitHub, GitLab and Slack tokens and AWS access key IDs, and `kardinalPromotion.redacted` lists what was changed ([Credentials are redacted](receipts.md#credentials-are-redacted), #2158). Off by default ([Signed promotion receipts](receipts.md)).
