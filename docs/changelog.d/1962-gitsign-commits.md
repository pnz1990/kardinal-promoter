- **Commit signatures with gitsign, and the agent that signed them** ([Commit signatures with gitsign](image-verification.md#commit-signatures-with-gitsign), #1962) — with `spec.imageVerification.commits.authorities`, kardinal verifies a config commit's gitsign (Sigstore) signature itself instead of asking the SCM, which cannot verify a short-lived Fulcio certificate. The signed payload is read from the GitHub, Forgejo or Gitea API, the commit SHA is recomputed from it, and the certificate, the signature and the embedded Rekor entry are checked offline against a keyless authority, as for images. `AgentIdentity.spec.signingIdentities` maps a verified signer to its agent: `status.commit` records `method`, `signer`, `issuer`, `authority` and `agent`, and a gate reads them as [`commit.*`](reference/cel-context.md#commit), for example `actor.kind != "agent" || commit.agent == actor.agent`. A keyless attestation's signer maps the same way (`attestations.<name>.agent`). GPG and SSH signatures stay on the SCM path (`requireSigned` without `authorities`). No new dependency: the check uses the CMS and Sigstore libraries kardinal already ships.
