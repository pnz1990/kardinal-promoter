section: Security
---

- **The actor policies refuse a stamp they cannot judge** (#2071, [How the actor is verified](actors.md#how-the-actor-is-verified)). The `<release>-actor-records` policy checks the stamps of pauses, hold releases, `spec.lastChange` and rejections. Before, it judged them against the agent index whatever the index's state. Now it refuses every stamped record while the index is not Ready, as `<release>-actor` already did for versions, Approvals and overrides. That covers an index not yet built, a full index (`IndexFull`), and v0.14's compact index after a rollback. In those states absence from the index reads as "not a registered agent", so an agent could have recorded a pause stamped as a person or a bot. Unstamped records and the controller's writes are unaffected. Against v0.14's compact index, every one of these policies says "kardinal's agent index is in the compact format of a newer release", not "not ready yet". A full index's refusal now says so ("kardinal's agent index is full (IndexFull: …): remove AgentIdentities or subjects until it fits") instead of "not ready yet; retry", which retrying could not fix.
