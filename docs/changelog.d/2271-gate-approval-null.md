- **A verify gate, or an approval gate that only reads `approvals.*`, works next to a gate with an approval policy** (#2271): in a version's Graph that also held a gate with `spec.approval`, such a gate's instance was refused by the API server (`spec.approval` rendered as null) and never created, so the environment waited for ever. This covered, for example, an agent verifier on an environment where kardinal adds its approval gate for agents' versions. Each gate collection of the Graph now renders `spec.approval` for all its gates or for none ([Agents as verifiers](agentic/verify-with-agents.md)). A version already stuck recovers when you upgrade: on the first reconcile after the upgrade from v0.12.x, the controller renders the Graph of every promoting version again, once, in place. A Graph that was working keeps the same nodes and the same objects (its PromotionSteps and gate instances); a stuck one gets the new collections, and the gate instance it was missing is created. On a kro install that runs with its alpha `CELOmitFunction` feature gate, where these mixed Graphs worked, the gates of such a Graph are deleted and created again once as they move to their new collections.
