- **`kardinal validate` checks the CRD schema, offline** (#1287). The CLI embeds the kardinal.io CRDs of its own version. Each kardinal.io document is checked against its CRD's OpenAPI schema, the same way the API server checks it before running CEL rules. Errors cover wrong types, enums, patterns, formats, bounds, required fields, and fields the API server would drop. Each error includes its path and the API server's message, for example `spec.environments[0].approval: Unsupported value: "manual": supported values: "auto", "pr-review"`. The check now covers every kardinal.io kind (Subscription, ScmProvider, Bundle and the rest), not only Pipelines and PolicyGates. A kind that kardinal.io doesn't define is an error. A value of the wrong type is now reported with its path; before, `validate` failed without printing why. The CRDs' CEL rules still run only on the API server (`kubectl apply --dry-run=server`). The CLI binary grows by about 2.6 MB. See [kardinal validate](reference/cli/kardinal-validate.md).
