- **Fleet operations** (#1835) — `kardinal pause <pipeline> --env <fleet>` and `kardinal resume <pipeline> --env <fleet>` pause one fleet: no further target starts, for any version, and the targets in flight finish, as when `maxUnavailable` is reached. The Pipeline's new `spec.pausedFleets` holds the list (update on `pipelines/pause`, as for `spec.paused`; the API server refuses an entry that is not a fleet environment), `kardinal get pipelines` and `status.summary` say the fleet is paused, and the UI API's `pause` and `resume` take an `environment`. `kardinal rollback --env <fleet>` of targets that run different versions (a rollout stopped part way) now goes back to the oldest version a target runs, instead of refusing, and refuses when that version was not Verified in a target it would change, naming each; it prints how many targets go back and from what, and `-o json` and the UI API's rollback response list each target's `runs` and `changes`. A paused fleet cannot be renamed or removed while paused (the chart's new `<release>-fleets` admission policy), and without the policy the pause fails closed. `kardinal hold --env <fleet>` holds every target when they run one version, instead of refusing every fleet. The UI fleet station shows a paused fleet and offers Pause fleet, Resume fleet and a rollback of the whole fleet. See [Pause one fleet](pause.md#pause-one-fleet) and [Roll back a fleet](rollback.md#roll-back-a-fleet)
