    Kubernetes promotion controller

    GitOps Governance for the Agentic Era

    Agents, CI and people ship changes the same way: kardinal promotes each version through your environments by writing to Git, and enforces governance where the change lands, in the cluster, not in the agent.

    • A verified actor and sponsor. Every version, approval and override records who acted, checked by the API server; a registered agent is recorded with the person who answers for it, and excludeAuthor keeps a version's creator from approving it.
    • A local MCP server. kardinal mcp runs with the agent's own kubeconfig, read-only unless started with --allow-write, and answers a policy pre-flight before the agent acts.
    • Agents as governed verifiers. A verify gate holds an environment until enough eligible agents, people or CI record passing verdicts on the version, never from the author agent's own party, with the evidence in the pull request.

    What you write¶

    One Pipeline per application. This one promotes through test and uat on its own, and opens a pull request for prod:

    apiVersion: kardinal.io/v1alpha1
kind: Pipeline
metadata:
  name: my-app
spec:
  git:
    url: https://github.com/myorg/gitops-repo
    secretRef: { name: github-token }
  environments:
    - name: test
    - name: uat
    - name: prod
      approval: pr-review

    By default each environment deploys the environments/<name> directory of the repository, and kardinal checks the Deployment my-app in the namespace <name>.

    How it works¶

    1. CI creates a version with the new image and where it came from.
    2. Each environment in turn gets the version written to Git (directly, or through a pull request), and kardinal checks its health.
    3. Gates hold the version out of an environment until their rules pass.
    4. A pull request is opened for review where an environment uses approval: pr-review, with the evidence in its body.

    Start with the Quickstart, then Concepts, which explains the four words this needs: version, pipeline, environment and gate. To install, see Install. To compare with Kargo and GitOps Promoter, see the comparison.
