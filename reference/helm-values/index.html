    Helm values¶

    Every value of the kardinal-promoter chart, with its default. Set them with --set or a values file; the chart's schema rejects an unknown key. The descriptions are the comments in values.yaml. Where a value sets a controller flag, the flag is in Controller flags.

    Key Default Description
    replicaCount 1 Number of controller replicas
    terminationGracePeriodSeconds 60 Pod termination grace period in seconds. Keep it above shutdownDelaySeconds plus the controller's 30s shutdown timeout: on SIGTERM the controller gives in-flight HTTP requests up to 20s, then cancels in-flight reconciles, and exits within 30s.
    shutdownDelaySeconds 5 Seconds a controller Pod being deleted keeps serving before it gets SIGTERM (a preStop sleep). Services stop sending it new connections meanwhile, so a rollout or a node drain does not refuse or drop UI, webhook and Bundle API requests. It counts against terminationGracePeriodSeconds. 0 sends SIGTERM at once.
    image.repository ghcr.io/pnz1990/kardinal-promoter/controller Container image repository
    image.pullPolicy IfNotPresent Image pull policy
    image.tag "" Image tag (defaults to chart appVersion)
    image.digest "" Image digest (sha256:...); when set the image is repository@digest and the tag is not used.
    imagePullSecrets [] Image pull secrets for private registries. The render Jobs get them too (--render-image-pull-secrets); they must exist in the Pipeline namespaces.
    nameOverride "" Override the name of the chart
    fullnameOverride "" Override the full name of the chart
    serviceAccount.create true Create a ServiceAccount
    serviceAccount.annotations {} Annotations to add to the ServiceAccount
    serviceAccount.name "" Override the ServiceAccount name
    podAnnotations {} Annotations to add to the controller Pod
    podSecurityContext {"runAsNonRoot":true,"seccompProfile":{"type":"RuntimeDefault"}} Security context for the controller Pod
    securityContext {"allowPrivilegeEscalation":false,"capabilities":{"drop":["ALL"]},"readOnlyRootFilesystem":true,"runAsNonRoot":true} Security context for the controller container
    logLevel info Controller log level: debug, info, warn or error. Sets both the reconciler logger (--log-level) and controller-runtime's logger (--zap-log-level; warn maps to error there, which has no warn level).
    leaderElect true Enable leader election for controller manager
    leaderElectionFlowSchema.enabled true Create the FlowSchema.
    leaderElectionFlowSchema.matchingPrecedence 90 Its matchingPrecedence. It must be lower (matched first) than any FlowSchema that matches the controller's other requests; the built-in workload ones are 9000 and above.
    leaderElectionFlowSchema.priorityLevel leader-election The priority level the Lease requests use.
    controller.tlsCertFile "" Path to the TLS certificate file (PEM). Set together with tlsKeyFile to enable TLS.
    controller.tlsKeyFile "" Path to the TLS private key file (PEM). Set together with tlsCertFile to enable TLS.
    controller.watchNamespace "" Namespace-scoped install mode (--watch-namespace). Empty = cluster-wide. When set, the controller caches and reconciles only this namespace, its namespaced permissions are a Role/RoleBinding there, and a small ClusterRole (<fullname>-cluster-scoped) covers ChangeWindows and get on this Namespace. It must equal the release namespace (install the chart into the namespace it watches); org-level PolicyGates are read from this namespace too.
    controller.namespaceShard "" Controller shard (--namespace-shard). Empty = no sharding: this controller reconciles every namespace. Set, it reconciles the namespaces labelled kardinal.io/shard=<name>; "default" also takes the namespaces without the label and the cluster-scoped kinds. Install one release per shard (one of them "default"), each in its own namespace labelled with its shard. Grants list/watch on Namespaces and Leases cluster-wide: each shard holds a Lease kardinal-shard in every namespace it reconciles. Cannot be combined with watchNamespace. See docs/sharding.md.
    controller.policyNamespaces [] Namespaces holding org-level PolicyGates (--policy-namespaces). Empty keeps the controller default, platform-policies. In namespace mode org gates are read from watchNamespace, and an entry other than watchNamespace fails the install.
    controller.gateStatusHeartbeat "" Longest a PolicyGate's status goes unwritten while its result does not change (--gate-status-heartbeat, a Go duration). Empty keeps the controller default, 10m. "0s" writes the status on every evaluation; each write makes kro re-check the gate's whole Graph.
    controller.workers {} Workers per controller: how many objects of a kind are reconciled at once (--promotionstep-workers, ...). One object is never reconciled twice at once. Unset keeps the controller defaults, measured with the scale suite: promotionStep 16, prStatus 8, policyGate 8, bundle 4, pipeline 4. Raise promotionStep for many Pipelines on slow git hosts. See docs/operate.md (Controller concurrency).
    controller.accessLog Access log of the UI API and the Bundle API: logins (TokenReviews), refusals (401/403/429, with the reason) and writes are always logged as structured lines (component=access). Tokens are never logged.
    controller.accessLog.allRequests false Log every request (--access-log-all-requests).
    controller.accessLog.sourceIP false Add the client address (--access-log-source-ip).
    controller.accessLog.trustedProxies [] CIDRs of proxies (an Ingress controller) whose X-Forwarded-For gives the client address (--access-log-trusted-proxies). Other clients' X-Forwarded-For is ignored.
    controller.accessLog.auditEvents true Write an AuditEvent (action APIWrite) naming the caller for every write through the UI API and the Bundle API (--api-audit-events).
    controller.gateOverrideMaxMinutes "" Longest a gate override counts, in minutes from when the controller first saw it (--gate-override-max-minutes): an override ends at the earlier of its expiresAt and this cap. Empty keeps the default, 1440 (24h).
    controller.freezeExemptionMaxMinutes "" Longest a freeze exemption (kardinal override --freeze) counts, in minutes from when the controller first saw it (--freeze-exemption-max-minutes): an exemption ends at the earlier of its expiresAt and this cap. Empty keeps the default, 1440 (24h).
    controller.extraArgs [] Extra controller args, e.g. ["--cors-allowed-origins=https://kardinal.example.com"].
    controller.extraEnv [] Extra env vars for the controller container (e.g. HTTPS_PROXY).
    controller.extraVolumes [] Extra volumes for the controller Pod (e.g. a TLS Secret).
    controller.extraVolumeMounts [] Extra volume mounts for the controller container.
    metricsBindAddress :8080 Address the metrics endpoint binds to
    healthProbeBindAddress :8081 Address the health probe endpoint binds to
    pprofAddress "" Address that serves Go pprof profiles under /debug/pprof/ (--pprof-address). Empty (the default) serves none. An address without a host, such as ":6060", binds to 127.0.0.1: reach it with kubectl port-forward. The profiles show heap contents, so no Service or container port exposes it. It has no authentication, and /debug/pprof/cmdline shows the process args: keep secrets out of controller.extraArgs.
    service.metricsPort 8080 Metrics port (Prometheus)
    service.healthPort 8081 Health/readiness probe port
    service.uiPort 8082 Embedded UI and UI API port (--ui-listen-address)
    service.webhookPort 8083 Webhook and Bundle API port (--webhook-bind-address): /webhook/scm and /api/v1/bundles
    resources {"limits":{"cpu":"500m","memory":"1Gi"},"requests":{"cpu":"10m","memory":"256Mi"}} Controller resources. The controller caches every Pipeline, Bundle, PromotionStep, PRStatus and PolicyGate it watches, so its memory grows with Pipelines times the Bundle history. Measured peaks (scale suite): 166 MiB for 200 Pipelines with a Bundle each, 409 MiB for 2 Bundles a second over 40 Pipelines with leader kills; 55-70 MiB with no Pipelines. The defaults give the larger load 2.5x headroom; see "Sizing the controller" in docs/operate.md.
    nodeSelector {} Node selector for the controller Pod
    tolerations [] Tolerations for the controller Pod
    affinity {} Affinity rules for the controller Pod
    github github.token and github.secretRef are the old names of scm.token and scm.secretRef (below) and keep working, for every scm.provider. Setting both names to different values fails the install.
    github.token "" Old name of scm.token.
    github.secretRef Old name of scm.secretRef.
    github.secretRef.name "" Old name of scm.secretRef.name.
    github.secretRef.namespace "" Old name of scm.secretRef.namespace.
    github.secretRef.key "" Empty is "token".
    github.app {"enabled":false} Authenticate as a GitHub App: the scm.secretRef Secret holds githubAppID, githubAppInstallationID and githubAppPrivateKey instead of a token. The controller mints installation tokens, refreshes them before they expire, and reloads the App credentials when the Secret changes. Needs scm.provider github (or empty) and scm.secretRef.name.
    actors SCM provider (--scm-provider): github (default when empty), gitlab, forgejo, gitea, bitbucket, azuredevops or bitbucket-datacenter, and its API base URL (--scm-api-url) for self-hosted instances. See docs/scm-providers.md. Identity admission policies (templates/identity-admission.yaml, docs/guides/security.md#verified-identity).
    actors.directory.public true Let every authenticated user read the agent registry (AgentIdentities and the AgentIndex): kardinal stamps what it writes from it (docs/actors.md). With false, bind the <fullname>-agent-directory-reader ClusterRole to the agents and people who use kardinal.
    admission.controllerUsernames [] Usernames, besides this release's controller ServiceAccount, that run a kardinal controller: they may name any Bundle's kardinal.io/created-by, write the objects a promotion Graph manages, and record or revoke the UI's Approvals (kardinal.io/recorded-via: ui). Exact usernames only, for example "system:serviceaccount:kardinal-system:kardinal-promoter-b"; there are no wildcards. Never list a ServiceAccount of a tenant's namespace: whoever can mint tokens for a listed ServiceAccount passes these checks.
    scm.provider "" SCM provider (--scm-provider): github (default when empty), gitlab, forgejo, gitea, bitbucket, azuredevops or bitbucket-datacenter. A Pipeline can name another with spec.git.providerRef. See docs/scm-providers.md.
    scm.apiURL "" API base URL of a self-hosted SCM (--scm-api-url); empty: the provider's public API.
    scm.token "" SCM token for scm.provider, for opening PRs and detecting merges. Set one of: Either way the controller reads GITHUB_TOKEN from the Secret and watches it, reloading the SCM provider when the token changes (no restart). Never label this Secret kardinal.io/referenceable, and never name it in a Pipeline's git.secretRef (the controller refuses that): see demo.secretRef for the demo Pipeline's own Secret, and docs/guides/security.md.
    scm.secretRef Existing Secret holding the token.
    scm.secretRef.name "" Name of an existing Secret in the release namespace that holds the SCM token (or the GitHub App credentials with github.app.enabled).
    scm.secretRef.namespace "" Must be empty or the release namespace: GITHUB_TOKEN is read with a secretKeyRef, which only reads the Pod's namespace.
    scm.secretRef.key "" Key of the token in the Secret. Empty is "token".
    scm.allowedRepositories [] Repositories the controller's SCM token may act on (--scm-allowed-repositories), as host/repository globs: "github.com/acme/*", "gitlab.example.com/platform/**" for every subgroup, "dev.azure.com/<org>/<project>/*" for Azure DevOps. Every SCM call for another repository is refused, and a Pipeline that would need the token for one is Ready=False/RepositoryNotAllowed with its steps failing before git-clone (exempt: its own existing git.secretRef Secret and no pr-review environment). Empty allows every repository the token can write to, and the controller logs a warning at startup. See docs/guides/security.md.
    scm.providersAllowInsecureHTTP false Let ScmProviders and ClusterScmProviders use an http:// spec.apiURL (--scm-providers-allow-http), for an in-cluster SCM without TLS. Off, a provider must use https://, so its token never crosses the network in clear text. Their API requests always go through the egress guard (no loopback, link-local or cloud metadata addresses).
    scm.instanceSigners [] Forgejo/Gitea only: the names or emails the instance signs commits with (its repository.signing SIGNING_NAME / SIGNING_EMAIL, --scm-instance-signers). Image verification treats such a commit as a platform signature (forgejo-instance). Without it, a verified signer that is not a user of the instance is taken as the instance key.
    scm.gatesCommitStatus {"context":"kardinal/gates","enabled":true} The gate results of a waiting pr-review step as a commit status on the commit kardinal pushed to its PR (docs/pr-evidence.md). enabled: false (--gates-commit-status=false) posts none, for a token without the commit-status permission. context (--gates-status-context) is the status name branch protection requires; it is reserved for kardinal.
    webhook {"secretRef":{"key":"secret","name":""}} Webhook secret for :8083/webhook/scm (KARDINAL_WEBHOOK_SECRET): the HMAC key, or for GitLab and Azure DevOps the plain token the SCM sends.
    bundleAPI Bearer token for the Bundle API, POST :8083/api/v1/bundles (KARDINAL_BUNDLE_TOKEN). The Bundle API is off until this is set.
    bundleAPI.tokenSecretRef.name "" Name of a Secret in the release namespace holding the Bundle API bearer token (KARDINAL_BUNDLE_TOKEN). The Bundle API is off until a token or tokenReview is set.
    bundleAPI.tokenSecretRef.key token Key of the token in that Secret.
    bundleAPI.tokenReview false Accept Kubernetes tokens on POST /api/v1/bundles (--bundle-api-tokenreview-auth): each caller is authenticated with a TokenReview and needs create on bundles (and get on the Pipeline) in the namespace, e.g. the promoter role. The static token, when set, still works as a single-tenant admin token.
    bundleAPI.acceptAPIServerAudience false Also accept tokens for the API server's own audience on the Bundle API (--bundle-api-tokenreview-accept-apiserver-audience): kubeconfig tokens of people, which also work against the API server. Off by default: CI mints a token for kardinal's audience instead. tokenReview.acceptAPIServerAudience (for the UI's SSO) does not apply here, and ServiceAccount tokens for the API server's audience, the one every Pod mounts, are refused even with this on.
    tokenReview TokenReview settings of ui.auth.tokenReview and bundleAPI.tokenReview.
    tokenReview.audiences ["kardinal-promoter"] Token audiences accepted (--tokenreview-audiences). Mint a token for kardinal with: kubectl create token <sa> --audience kardinal-promoter. Such a token is refused by the API server itself, so kardinal cannot replay it there. At least one, unless acceptAPIServerAudience is set.
    tokenReview.acceptAPIServerAudience false Also accept tokens for the API server's own audience on the UI API (--tokenreview-accept-apiserver-audience): kubeconfig tokens, and the OIDC ID tokens an SSO proxy forwards. Such a token also works against the API server, so whoever holds kardinal's traffic can use it there; opt in knowingly. ServiceAccount tokens for the API server's audience, the one every Pod mounts, are refused even then. The Bundle API has its own switch, bundleAPI.acceptAPIServerAudience.
    ui Embedded UI (:8082).
    ui.corsAllowedOrigins [] Origins allowed by CORS on the UI API (--cors-allowed-origins).
    ui.allowedHosts [] Extra host names the UI answers to (--ui-allowed-hosts), for example an Ingress host or a node IP. The Service DNS names (<fullname>, <fullname>.<namespace>, .svc and .svc.cluster.local) and localhost are always allowed. Browser requests to any other Host get no same-origin grant, and while UI auth is off every UI API request to them, reads included, gets 403 (DNS rebinding protection). Static /ui/ assets are not checked. Host names only: no scheme, path or wildcard.
    ui.auth.tokenSecretRef {"key":"token","name":""} Static bearer token for /api/v1/ui/* (KARDINAL_UI_TOKEN).
    ui.auth.tokenReview false Validate UI bearer tokens as Kubernetes ServiceAccount/user tokens (--ui-tokenreview-auth). Adds tokenreviews and subjectaccessreviews create to the controller's ClusterRole.
    ui.auth.allowStaticTokenWithTokenReview false Install even when tokenSecretRef.name and tokenReview are both set (--ui-auth-static-overrides-tokenreview). The static token then wins and every UI caller acts as the controller, so by default that combination fails the install.
    ui.freezeControls false Offer Freeze agents, Stop the line and Unfreeze in the UI (--ui-freeze-controls; docs/agentic/freezes.md). Needs auth.tokenReview: a freeze names who froze. Grants the controller create, update and delete on ChangeWindows; the <fullname>-freezes admission policy admits its writes only as freezes, with the caller as spec.freeze.createdBy. Off, the UI shows freezes and kardinal freeze writes them.
    health Health checks of the PromotionSteps.
    health.refresh.enabled true Ask the GitOps tool to sync a promotion's commit as soon as it is in git (--health-refresh), once per step, instead of waiting for its poll (Argo CD: 3 minutes by default): argocd.argoproj.io/refresh on the Application of health.type argocd, reconcile.fluxcd.io/requestedAt on the Kustomization of health.type flux and its GitRepository. Grants patch on argoproj.io Applications, Flux Kustomizations and GitRepositories; the <fullname>-gitops-writes admission policy denies the controller any change to them but that annotation unless it may update the object. An environment's health.refresh: false turns it off there. See docs/health-adapters.md#sync-on-promotion.
    health.refresh.namespaces [] The Applications and Kustomizations of this cluster a Pipeline may have the controller refresh (--health-refresh-namespaces), besides those in its own namespace or deploying there (spec.destination.namespace, spec.targetNamespace): pipelineNamespace=namespace rules, each side a namespace, a prefix ending in * or . For example ["default=kardinal-test-app-"]; ["="] refreshes any object. Other objects are not refreshed and the step waits for the tool's poll.
    rbac Optional controller permissions, off by default.
    rbac.argocdApplicationsWrite false patch and update on argoproj.io Applications, for the argocd update strategy (update.strategy: argocd). update is what lets the controller change an Application's spec past the gitops-writes admission policy, which otherwise allows only the refresh annotation (health.refresh).
    rbac.userRoles.enabled true ClusterRoles for users and automation: <fullname>-viewer, -promoter, -approver and -admin (templates/user-roles.yaml). Bind them per namespace with RoleBindings. See docs/guides/security.md#user-roles.
    rbac.userRoles.aggregateToDefaultRoles false Also aggregate them into the built-in view (viewer), edit (promoter, approver) and admin ClusterRoles. Off by default: with it, everyone bound to edit can both promote and approve gates in that namespace.
    rbac.userRoles.directWrites false Also grant the promoter update on Pipelines and the approver update on PolicyGates, so kardinal pause, kardinal rollback --hold, kardinal unhold and kardinal override work from their kubeconfigs. An admission policy limits those writes to spec.paused, spec.pausedFleets and spec.holds (Pipelines; the hold-writes policy checks each hold entry) and spec.overrides (PolicyGates). Off: they act through the UI API only. On weakens the audit trail: those writes are the user's own, with no requested-by record from kardinal, and createdBy is checked only by the policy.
    graph kro Graph integration. kardinal renders one kro Graph (kro.run/v1alpha1) per Bundle. kro v0.10.0-rc.0 or later with the GraphKind feature gate must be installed separately: kro applies each Graph's children by impersonating graph.serviceAccountName in the Graph's namespace; the controller creates that ServiceAccount and binds it to the ClusterRoles below with RoleBindings.
    graph.serviceAccountName kardinal-graph ServiceAccount kro impersonates for each Graph.
    graph.kroNamespace kro-system Namespace kro runs in. Only used for a NetworkPolicy egress rule; "" drops that rule.
    graph.readerNamespaces ["argocd","flux-system"] Namespaces, besides a Graph's own namespace, where the controller may bind the Graph ServiceAccount to the reader ClusterRole so the Graph can read health objects (Argo CD Applications, Flux Kustomizations, Deployments). A health check in any other namespace gets no Graph ref and a warning; the PromotionStep health check itself is unaffected. "*" allows every namespace except kube-system, kube-public and kube-node-lease: use it only when every Pipeline author may read every namespace.
    graph.aggregateToKro true Ship a ClusterRole aggregated into kro's controller role, for kro installed with rbac.mode=aggregation (the hack/install-kro.sh default).
    graph.compactAbove null Environment count above which a Bundle's Graph uses the compact shape (--graph-compact-above): one PromotionStep collection instead of one node per environment. null keeps the controller default, 100; 0 makes every Graph compact. A Pipeline's kardinal.io/graph-shape annotation overrides it.
    graph.retire When the Graph of a finished Bundle is retired: deleted, with the Bundle's PromotionSteps kept in status.retiredSteps. kro holds every Graph in memory (3 to 6 MB each), so keeping the Graph of every finished Bundle until spec.historyLimit prunes it runs kro out of memory. Go durations; empty keeps the controller default; "0s" keeps those Graphs. A Pipeline's kardinal.io/graph-retire-after annotation replaces all three for its Bundles. See docs/operate.md#sizing-kro.
    graph.retire.superseded "" A Superseded Bundle, or a Verified one that a newer Bundle replaced in every environment (--graph-retire-superseded-after, default 1m).
    graph.retire.failed "" A Failed Bundle (--graph-retire-failed-after, default 24h). A retired Failed Bundle does not recover.
    graph.retire.verified "" A Verified Bundle still deployed in an environment (--graph-retire-verified-after, default 1h).
    hooks Pipeline pre- and post-deploy hooks (spec.environments[].hooks, docs/hooks.md). The controller runs each hook as a Job in the Pipeline namespace.
    hooks.serviceAccounts ["default"] ServiceAccount names a hook's Job Pod may run as (--hook-service-accounts), in the Pipeline namespace. A hook whose Pod names another one fails without running. Anyone who can edit a Pipeline can run a Pod as one of these, so list only ServiceAccounts with the rights a hook needs. The Graph ServiceAccount (graph.serviceAccountName) is never allowed.
    hooks.podSecurityLevel baseline Pod Security Standard a hook's Pod must meet (--hook-pod-security-level): baseline (no privileged containers, host namespaces, hostPath volumes, added capabilities beyond the baseline set...), restricted (also non-root, no privilege escalation, seccomp RuntimeDefault, all capabilities dropped), or privileged (no Pod checks). Below privileged, nodeName and hostPort are refused too. A hook that breaks it fails without running.
    render Rendered manifests (layout: branch, docs/rendered-manifests.md). Each render runs as a Job in the Pipeline's namespace from this image, never in the controller: no Kubernetes credentials (the ServiceAccount below gets no role and no token), a read-only root filesystem, no capabilities, and these limits. It reads the DRY source and pushes the render with the Pipeline's own git Secret (spec.git.secretRef).
    render.image.repository ghcr.io/pnz1990/kardinal-promoter/render kardinal-render image repository.
    render.image.tag "" Tag (defaults to chart appVersion).
    render.image.digest "" Digest (sha256:...); when set the image is repository@digest and the tag is not used.
    render.image.pullPolicy "" imagePullPolicy of the render Jobs (empty: Kubernetes' default).
    render.serviceAccountName kardinal-render ServiceAccount the render Pods run as. The controller creates it in a Pipeline namespace that has none, without a token; bind no role to it.
    render.resources.limits.cpu 1 CPU limit of a render Job.
    render.resources.limits.memory 512Mi Memory limit of a render Job. A render that needs more fails.
    render.timeout 5m How long a render Job may run.
    render.networkPolicy NetworkPolicy for the render Pods: egress only to DNS and the git host. Needs a CNI that enforces NetworkPolicy. It is created in each of namespaces (the Pipeline namespaces that use layout: branch).
    render.networkPolicy.enabled false Create the render NetworkPolicy.
    render.networkPolicy.namespaces [] Namespaces to create the render NetworkPolicy in.
    render.networkPolicy.gitEgress [] Egress rules (NetworkPolicyPeer lists with ports) for the git host, e.g. [{to: [{ipBlock: {cidr: 140.82.112.0/20}}], ports: [{port: 443, protocol: TCP}]}].
    tracing.enabled false Export OpenTelemetry traces over OTLP/HTTP (--tracing-enabled): spans for reconciles, promotion steps, git clone/push, SCM API calls and NotificationHook deliveries (which carry a traceparent header), and server spans for /webhook/scm and /api/v1/bundles. See docs/guides/monitoring.md.
    tracing.endpoint "" OTLP/HTTP endpoint: a URL (http://otel-collector.observability:4318) or host:port. Empty uses OTEL_EXPORTER_OTLP_ENDPOINT (set it with controller.extraEnv), else localhost:4318.
    tracing.insecure false Plain HTTP to a host:port endpoint (a URL's scheme decides by itself).
    tracing.samplingRatio 0.1 Fraction of traces recorded, 0 to 1, decided at each trace's root. An inbound traceparent is linked, not trusted, so it does not force recording.
    egress.allowlist [] Destinations NotificationHook, MetricCheck and Subscription requests may reach (--egress-allowlist): host names (hooks.slack.com), wildcards (*.example.com: any name under it) and CIDRs or addresses (10.0.0.0/8). A request is allowed when its host matches a name or every address it connects to is in a CIDR. Empty: any destination except loopback, link-local, cloud metadata, unspecified and multicast addresses, which stay refused whatever this lists. See docs/guides/security.md.

    audit AuditEvent retention, on by default. AuditEvents have no owner, so without retention they stay in etcd for ever, and a full etcd quota stops the whole cluster. The leader deletes, every 10 minutes, the records older than maxAge and, per Pipeline, all but the maxPerPipeline newest (records that name no Pipeline share one cap per namespace), at most 2000 a run at 5 API requests a second; the chart grants the controller delete on AuditEvents. enabled: false keeps every record. Upgrading deletes the records already past these limits: export them first if you must keep them. See docs/guides/security.md (Retention).
    audit.retention.enabled true Delete AuditEvents past maxAge and maxPerPipeline (--audit-retention). false keeps every record.
    audit.retention.maxAge 2160h Delete records created longer ago than this (--audit-retention-max-age, a Go duration). "0s" keeps records of any age.
    audit.retention.maxPerPipeline 1000 Keep this many newest records per Pipeline (--audit-retention-max-per-pipeline). 0 keeps any number. A gate that flips often writes a record per flip and reaches it quickly. A record created in the last 10 minutes is kept even past it.
    metricCheck MetricCheck providers.
    metricCheck.cloudWatch.ambientCredentials false Let cloudwatch MetricChecks that name no credential Secret use the controller's own AWS identity (IRSA, EKS Pod Identity, environment). Off by default: anyone who can create a MetricCheck could then read CloudWatch with that identity. Annotate serviceAccount for IRSA.
    metricCheck.querySlots {"global":12,"perNamespace":1} Outbound MetricCheck query slots. Every provider dials an address the MetricCheck's author chose, so queries are capped: at most global run at once in the cluster, at most perNamespace per namespace, and the rest wait first come, first served (status reason WaitingForSlot). The sustained throughput is about global / query time: with 12 slots and 0.5 s queries, 24 queries a second, so 1,440 MetricChecks at a 60 s interval. One namespace gets at most perNamespace / query time. The MetricCheck controller runs global + 4 workers (at least 16), so every slot can be used.
