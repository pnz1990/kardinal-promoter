    kardinal¶

    kardinal manages promotion pipelines on Kubernetes

    Synopsis¶

    kardinal promotes versions of your application through environments, with gates, pull requests and health checks, on Kubernetes.

    Getting started: kardinal quickstart --repo try it on a local cluster kardinal init --name my-app --repo write a Pipeline for your repository kardinal ship my-app --image app:1.4 --wait ship a version and follow it kardinal why my-app prod why it waits, and what moves it on

    Output follows where it goes. On a terminal, each state reads as a glyph and its label in the status colours of the UI, from its design tokens (web/tokens/tokens.json): Live (spruce), Promoting and Checking health (thread red), Waiting for PR merge and gates not ready yet (dusk blue), Held by gate (ochre), Failed (on garnet, the only filled state), Replaced by newer version and Not reached (grey); Paused and Held by rollback are bold. Without COLORTERM=truecolor and a COLORFGBG that names the background, they are the nearest of the 16 ANSI colours, which the terminal's theme adapts. Without a UTF-8 locale the glyphs are ASCII (* Live, ~ Waiting for PR merge).

    Piped to a file or another program, or with NO_COLOR (any value) or TERM=dumb, output is plain words: the labels without glyphs or colour. The cluster's text (a step's message, a Pipeline's summary) passes through as it is when the locale is UTF-8 (LC_ALL, LC_CTYPE or LANG); without a UTF-8 locale, or with TERM=dumb, everything is ASCII (a dash is "-", an arrow "->", any other non-ASCII character "?"). On Windows, colour needs a console with virtual-terminal processing; without it output has no colour.

    -o json and -o yaml print the API's values (Verified, WaitingForMerge) and the cluster's text unchanged, and no table placeholders ("-", "--", "..."): a field with nothing to say is left out. With -w, -o json prints one document per refresh and -o yaml separates them with "---". Hints, prompts and the CLI's own warnings go to stderr, so stdout stays valid JSON. The notices a report shows about what it read (the ERROR: and WARNING: lines of status, get pipelines and explain) are part of its output, on stdout, so kardinal status my-app | less shows them; with -o json they are fields. get prints the objects as the API server lists them. The others print these fields (in brackets the ones left out when empty):

    create bundle, promote, rollback: bundle, pipeline, namespace, url, [type, version]; promote adds environment and from (the Bundle copied); rollback adds environment, rollbackOf (the Bundle restored), [replaces] (the one replaced) and, with --hold, hold {environment, bundle, [reason, expiresAt]} create bundle --dry-run: pipeline, namespace, nodes, environments [{name, [gates]}] in promotion order, [type, version, compact] unhold (release-hold): pipeline, namespace, environment, bundle (the version it was held on), url, [createdBy, reason] status: controller, pipelines, bundles, activeBundles, [degraded] (namespace/name) status : pipeline, namespace, source ("controller" or "cli"), environments, blockingGates, [phase, paused, summary, notices, warnings, regions]; an environment is status.environments' entry: name, [bundle, version, incomingBundle, incomingVersion, state, since, blockedBy, prURL, held]; a gate: name, instance, environment, bundle, expression, [message, reason, lastEvaluatedAt] explain: pipeline, namespace, entries [{environment, bundle, type (Step or PolicyGate), name, state, [expression, reason]}], [holds [{environment, bundle, [createdBy, reason, bundleMissing]}]] history: a list of {bundle, action (promote or rollback), environment, state, createdAt, [prURL, durationSeconds, running]}: durationSeconds once the step ended, running while it runs ship: the create bundle fields and exitCode, with --wait also [result, message, environments]

    url is the pipeline in the UI: KARDINAL_UI_URL, else the address kardinal dashboard opens (http://localhost:8082/ui/). For example kardinal create bundle my-app --image app:1.4 -o json | jq -r .bundle names the new Bundle.

    Options¶

          --context string      Kubeconfig context override
  -h, --help                help for kardinal
      --kubeconfig string   Path to kubeconfig file (default: $KUBECONFIG, else ~/.kube/config)
  -n, --namespace string    Kubernetes namespace (default: current context namespace)
  -o, --output string       Output format: table (default), json, yaml, wide (json and yaml: create bundle, explain, get auditevents, get bundles, get pipelines, get steps, get subscriptions, history, hold, inbox, promote, rollback, ship, status, unhold, why; wide: get subscriptions, status, why)
