    kardinal status¶

    Show controller health or per-pipeline in-flight promotion details

    Synopsis¶

    Without a pipeline: the controller and its readiness, the counts, and one line per pipeline with its summary. With one: per environment, the version running there, a newer one on its way in, its state and since when, its PR, and the gates holding it back. Run it first when a promotion is stuck; -w refreshes it and -o json prints it for scripts.

    When called without arguments, across every namespace (-n for one). When you may not list every namespace it shows the kubeconfig's, with a note on stderr; with -A, which asks for every namespace, it fails and says to use -n:

    Controller: v0.10.1 in kardinal-system, 1/1 ready Pipelines: 3 (1 degraded: team-b/api) Versions: 5 (3 in flight)

    NAMESPACE PIPELINE SUMMARY team-a web 1.5.0 live in test, prod team-b api A version failed team-c edge 7.2.0 live in canary and 27 of 42 pops; promoting in 5 pops; queued in 10 pops

    Details: kardinal status -n

    the controller version (the kardinal-version ConfigMap in --controller-namespace) and how many replicas of its Deployment are ready (else "no controller Deployment found there: kardinal doctor", or "can't read the controller Deployment (needs list on deployments in )": the chart's user roles do not grant it; fewer ready than desired is a warning), the pipeline count with any Degraded pipelines, the version count (in flight = Available or Promoting), and one line per pipeline (at most 50; then kardinal get pipelines -A) with its status.summary sentence (its phase from a controller that predates it). -o json adds controllerReady, controllerHealth {ready, reason}, namespace and note (when it is not every namespace) and items [{namespace, pipeline, phase, summary}] to controller, pipelines, degraded, bundles and activeBundles.

    When called with a pipeline name: first the Pipeline's own problems, an ERROR when it is not Ready (such as GitCredentialMissing, with the command that creates the git Secret, or SecretNotReferenceable, with the command that labels it kardinal.io/referenceable=true); then the Pipeline's summary sentence ("1.5.0 live in test; waiting for PR merge in prod (#42)"), then one row per environment (a fleet environment expands to its targets) from the Pipeline's status.environments, which the controller writes:

    RUNNING the Bundle whose change runs there, with its version INCOMING a newer Bundle on its way in, with its version STATE where the newest Bundle there stands, in words ("Live", "Waiting for PR merge", "Held by gate no-weekend-deploys", "Held by rollback") SINCE how long it has been in that state PR the pull request it waits for, while it waits for its merge

    REGION, after ENVIRONMENT, shows where each environment runs when one of them health-checks another cluster: the health.kubeconfigSecretRef Secret. -o wide adds ACTIVE STEP, the step the newest Bundle there is on (git-clone, open-pr, health-check, ...).

    Then the gates holding a version back, with their CEL expression cut to 40 characters, their message and when each was last checked; and a WARNING: line for a Rejected Bundle whose change still runs somewhere, with the rollback that removes it. A pipeline nothing was shipped to yet says so, with the command that ships the first version.

    With a controller older than status.environments, the CLI computes the same rows itself, with the controller's code; SINCE is then known only for live environments. -o json and -o yaml print the same data with the API's state values (Verified, WaitingForMerge) and "source": "controller" or "cli". kardinal explain shows the steps and every gate of the current Bundle.

    kardinal status [<pipeline>] [flags]

    Examples¶

      kardinal status
  kardinal status my-app -w
  kardinal status my-app -o json | jq -r '.environments[] | .name + "=" + .version'

    Options¶

      -A, --all-namespaces                Without a pipeline: every namespace (the default unless -n names one)
      --controller-namespace string   Namespace kardinal-promoter is installed in (default "kardinal-system")
  -h, --help                          help for status
  -w, --watch                         Refresh every 2 seconds (Ctrl-C to quit)

    Options inherited from parent commands¶

          --context string      Kubeconfig context override
      --kubeconfig string   Path to kubeconfig file (default: $KUBECONFIG, else ~/.kube/config)

  -o, --output string       Output format: table (default), json, yaml, wide (json and yaml: create bundle, explain, get auditevents, get bundles, get pipelines, get steps, get subscriptions, history, hold, inbox, promote, rollback, ship, status, unhold, why; wide: get subscriptions, status, why)
