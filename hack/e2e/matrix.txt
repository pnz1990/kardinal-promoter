# Every live e2e job: one kind cluster each, set up by hack/e2e/up.sh SUITE.
# hack/e2e/all.sh runs them on this host, JOBS at a time, in this order
# (longest first), and .github/workflows/e2e-live.yml runs them in CI
# (all.sh -matrix prints its matrix). A suite's minors and shards are here,
# nowhere else; test/hack checks that every suite in up.sh has a line, that
# core runs on every KIND_NODE_1_* minor in hack/tool-versions.env and that
# upgrade runs on the oldest of them, the oldest minor kardinal supports.
#
# suite           Kubernetes  shard  host  [pinned]
#   shard: hack/e2e/run.sh SHARD; - for the whole suite
#   host: heavy, and hack/e2e/local-live.sh takes the heavy-load lock and
#   drains the host for the suite (no new runs start, it starts with at most
#   one other cluster slot in use and the load under 16); - for a suite
#   that needs only a cluster slot. Every line of a suite says the same.
#   pinned: the suite cannot run on any other minor. The release gate and
#   all.sh MINORS run every other suite on the oldest and the newest minor
#   whatever its lines say, and the nightly sample on the minors they don't
#   list; a pinned suite runs on its own minors only, and the gate reports
#   the other minor as pinned, with the comment right above the suite's
#   first line as the reason (one is required, in words). Every line of a
#   suite says pinned, or none does. A pinned suite lists only minors of
#   hack/tool-versions.env, one of them the oldest or the newest; core cannot
#   be pinned, and an upgrade suite cannot be pinned off the oldest. The
#   release gate refuses any other pin before it runs.
