# The budgets of the agent scale scenario (test/scenario/enterprise/agents/
# scale, agentcases.RunScale): "scale.<mode>.<name> <value>". Mode quick is
# go test ./... (under -race in CI: 150 AgentIdentities, 3 tenants); mode
# full is KARDINAL_SCENARIO_ENTERPRISE=full (CI's scenario-enterprise job
# and the release gate, no -race: 5,000 AgentIdentities, 200 Pipelines in
# 50 tenants, 98 agents, 3 bursts). The scenario fails when a measure goes
# past its budget.
#
# Rounds and reconciles are counted, not timed, so the host's load does not
# move them. Measured (2026-10-16): 23 rounds per burst in both modes;
# reconciles per version of a burst 173, 314, 459 (each burst also wakes
# the Pipeline's earlier versions).
#
# The admission p99s are timed in the API server's ValidatingAdmissionPolicy
# plugin with the chart's policies, as #1959's envtest bound
# (TestActorPolicyLatencyOnAPIServer: p99 under 50ms, 44ms at 4,200 agents)
# times them on kube-apiserver, after the bursts: every agent's version,
# Approval and gate instance admitted again (writing nothing) in three
# passes over them all, each write's fastest timing kept, so that a spell of
# load on the host or a GC pause does not count (#2035). Measured in full on #1959 (dev host): agents' Bundle
# creates and people's Approvals p50 42ms, p99 46ms; kro's gate creates
# p99 0.16ms. Bundles and Approvals convert the whole index per request,
# linear in its size, so their budget is #1959's 50ms at 4,200 agents
# scaled to 5,000 (#2071); kro's guards #1936's fix (it converted the
# index too, tens of ms, before it). Quick mode runs under -race and keeps
# wide budgets.
